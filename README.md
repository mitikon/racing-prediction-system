# 競馬予想システム開発

このリポジトリは競馬予想システム専用です。

## 完全分離
- **部分空間正則化PCA＋先行シグナル予測λ（米国株式市場）** は別リポジトリ `mitikonpro` で管理し、このリポジトリには含めません。
- **本格先行予測λ・簡易式先行予測λ・部分空間正則化PCA一式**は、実戦検証（2026-09-13〜09-21、計20レース）で成績が悪化し「1着4着」等の僅差の券外が繰り返し発生したことを受け、2026-09-23に完全削除しました。関連するRSI再帰的自己改善（パラメータ昇格機構）・λ⇔WSI適応接続も、削除対象がなくなったため同時に削除しています。現行の中核は下記「予想4頭抽出方式」です。

## 予想4頭抽出方式（PCA非依存の予測中核）

`four_horse_extraction.py`が現在の予測中核です。部分空間正則化PCAには一切依存しません。

- **入力**: 出馬表・成績欄の写真、または対象レースを指定したプロンプト
- **予想の生成**: 定量式では計算しません。写真・プロンプトを読んだ人間またはLLMが直接判断し、ちょうど4頭を順位付きで抽出します
- **全頭レビューの徹底（必須）**: 出走全馬のオッズ・馬体重・直近成績・騎手/調教師/生産牧場を、一頭も漏らさず確認したことを`reviewed_horse_numbers`（`field_size`と同数、重複不可）で証跡として残します。一部の目立つ馬だけを見て4頭を選ぶ凍結予測は`ValueError`で拒否されます。過去の検証で、実際の3着以内馬が事前記録に一切言及がなく見逃されていたケースが繰り返し見つかったため、大衆と同じ公開情報を「一部だけ」ではなく「漏れなく」読むことをコードで強制しています
- **人気に関わらない脚質レビューの徹底（必須、2026-09-27追加）**: 出走全馬の脚質（逃げ・先行・差し・追込等）を`running_styles`（`reviewed_horse_numbers`と同一集合、重複・空値不可）で記録し、想定レース展開を`pace_scenario`として明示します。2026-09-27スプリンターズSの答え合わせで、直近好タイム・上位人気の馬を偏重し、中位人気の先行馬（結果は2着・3着）の展開適性を実質的に軽視していたことが判明したため追加しました。特定レースの結果に合わせて「穴馬を当てる」ロジックを作ることは後付け禁止ルールに反するため行わず、代わりに今後のどのレースにも同じ形で適用できる一般ルールとして、人気・オッズを見る前に全頭の脚質とペース適性を書き出すことを強制する形にしています
- **このモジュールの役割**: 生成された4頭を発走前に`open("x")`で排他的に凍結保存し、結果判明後に馬連・ワイド・三連複・三連単それぞれの機械的な的中判定と、「予想した馬が実際には4着だった」ような僅差の取りこぼしを`near_miss_horses`として定量記録します
- `EXTRACTION_METHOD = "photo_prompt_manual_extraction"`・`EXTRACTION_COUNT = 4`・全頭レビュー強制・脚質レビュー強制は保守専用RSI（`racing_maintenance_rsi`）が固定監査します

```bash
python -m pytest tests/test_four_horse_extraction.py
```

## 予想4頭抽出方式の実戦成績（定点観測）

`EVALUATION`が記録された全レースの集計値。結果を見てから`four_horse_extraction.py`のロジックを変更することはしておらず、この数字自体が選出基準を直接変えることもない（後付け禁止ルール）。あくまで母数が増えるまでの定点観測として記録する。

最終更新: 2026-10-10時点、計7レース

| 指標 | 結果 |
|---|---|
| 勝馬捕捉（winner_captured） | 5/7 |
| 馬連的中 | 1/7 |
| ワイド的中 | 1/7 |
| 三連複的中 | 0/7 |
| 三連単的中 | 0/7 |
| top3的中数（平均、predicted上位3頭ベース） | 1.0/3 |
| 僅差の取りこぼし（`near_miss_horses`該当） | 2/7レース |
| 4位指名（最終候補）が実際に馬券圏内 | 3/7レース |

n=7はまだ傾向の有無を判断するには少なすぎる。特に「見送りと明記した馬が実際に馬券へ絡む」パターンが複数回発生している点、4位指名が的中圏に来る頻度が比較的高い点は、今後のレースでも観察を継続する。

```bash
python3 -c "
import json
from pathlib import Path
rows = [json.loads((d / 'EVALUATION' / 'four_horse_evaluation.json').read_text())
        for d in sorted(Path('data/four_horse_extraction').iterdir())
        if (d / 'EVALUATION' / 'four_horse_evaluation.json').exists()]
n = len(rows)
print('n races:', n)
print('winner_captured:', sum(r['winner_captured'] for r in rows), '/', n)
print('umaren_hit:', sum(r['umaren_hit'] for r in rows), '/', n)
print('wide_hit:', sum(r['wide_hit'] for r in rows), '/', n)
"
```

## オッズ急変動アラート（仮説段階）

- これは「当たる根拠」として確立した指標ではなく、**仮説として都度記録する検討材料**です

- オッズ情報を共有いただくたび、この基準に該当する馬があれば直ちに報告します

## 市場織り込み3着以内確率（仮説段階・2026-10-08追加）

`market_probability.py`は、出走全馬の単勝オッズから、各馬の3着以内確率を推定します。

- JRA統計で一般に知られる「同じ1番人気でもオッズ水準で複勝率が大きく違う（抜けた本命ほど複勝率が高く、混戦の1番人気ほど低い）」という傾向を、特定レースの結果に合わせて作った係数ではなく、単勝オッズを確率に変換する標準的な統計モデル(Harville, 1973)で定量化したもの
- `implied_win_probabilities`でオッズの逆数を控除率(オーバーラウンド)で正規化し市場の勝率を求め、`harville_top3_probabilities`でPlackett-Luceモデルに基づき3着以内確率を推定する
- `estimate_favorite_top3_probability`は出走全馬のオッズから1番人気(最低オッズ)を自動特定し、「1番人気だから来るはず」という決めつけを避けて、そのオッズ水準から実際に見込まれる3着以内確率を数値で確認する
- `compare_favorite_and_runner_up`(2026-10-09追加)は1番人気と2番人気の単勝オッズ差から、両者の3着以内確率とその差をHarvilleモデルで比較する。オッズ差が大きい(=市場が1番人気に強い確信を持っている)ほど理論上は1番人気の3着以内確率が高く2番人気との差も開く、という傾向を実際のレースの全馬オッズから計算して確認する用途
- `rank_odds_gap_probabilities`(2026-10-09追加)は「オッズ差が大きいほど3着以内確率の差も開く」という傾向を1番人気・2番人気の組だけに限定せず、全馬を人気順(オッズ昇順)に並べたうえで隣接するすべての組(1位↔2位、2位↔3位、…最下位の組まで)について同じHarvilleモデルの3着以内確率とオッズ差を一括して求める。`compare_favorite_and_runner_up`の1番人気分を取り出すと同じ値になる、その一般化にあたる。各馬について「一つ上の人気の馬との差」と「一つ下の人気の馬との差」を両方返すため、1番人気・2番人気以外の馬についても同じオッズ差の考え方を検討材料として使える
- 展開・脚質・馬場適性・騎手/調教師評価などは一切考慮しない純粋なオッズの確率変換であり、予想4頭抽出方式には自動接続しない。`running_styles`・`pace_scenario`による全頭レビューと並ぶ検討材料として、オッズが共有された際に都度参照する。2026-10-04大原ステークスでは1番人気(1.7倍)の理論上の3着以内確率88.4%に対し実際は9着に終わっており、理論値通りにいかないケースも当然あることを記録しておく

```bash
python -m pytest tests/test_market_probability.py
```

## JRA実測統計による1番人気オッズ帯別複勝率（仮説段階・2026-10-08追加）

`jra_favorite_statistics.py`は、Harvilleの理論モデルとは別に、公開されている集計記事から収集した**1番人気限定の実測複勝率レンジ**を保持します。

- 各参考値は`verified`フラグで出典の確度を区別する
  - `verified=True`(単勝1.0〜1.9倍・3.0〜3.9倍): JRA-VAN「DATA DRIVEN DERBY」(G1限定・過去10年)、うまめし(umameshi.com)の1番人気複勝集計記事など、個別のURL・記事名まで特定できる出典(2026-10-08にWeb検索で収集。出典ごとに集計期間・対象レース範囲が異なるため範囲として保持)
  - `verified=False`(単勝2.0〜2.9倍・4.0倍以上): 独自のWeb検索を複数回行っても1番人気限定の確認済み出典が見つからなかった帯。ユーザーがGemini(Google検索)に要約させた値(2026-10-08提供)を、一次URL出典未確認と明記した上で収録している
- `lookup_favorite_place_rate_reference(odds)`で1番人気のオッズから該当する複勝率の参考レンジを引く。該当する参考値が一切見つかっていないオッズ帯は無理に補間せず`None`を返す
- 単勝1.0〜1.4倍で複勝率81.3〜89.7%(verified)、1.5〜1.9倍で73.8〜80%超(verified)、2.0〜2.9倍で約65〜67%(unverified)、3.0〜3.9倍で約50%(verified)、4.0倍以上で約40〜45%(unverified)という参考値を保持する
- `market_probability.py`のHarville理論値と併記して参照する検討材料であり、予想4頭抽出方式には自動接続しない

```bash
python -m pytest tests/test_jra_favorite_statistics.py
```

## 「RSI」の定義

このリポジトリで「RSI」という略称は`racing_maintenance_rsi`（保守専用RSI: コード整合性・秘密情報・危険なコードパターン・GitHub Actionsの監査）だけを指します。相対力指数（Relative Strength Index、Wilderの計算式）は**WSI（Wilder Strength Index）**と呼び分け、`wsi_self_learning.py`に実装します。かつて存在した予測パラメータ昇格用のRSI（再帰的自己改善）は、対象パラメータ（本格・簡易式λ）ごと2026-09-23に削除しました。

## WSI自己学習
- 全券種の市場支持率について5・7・14・21回のWilder Strength Index（WSI）を生成する生計算（`wsi_self_learning.py`）
- WSI水準、3観測変化速度、50突破、30/70圏の継続・離脱を特徴量化
- 同一レースのRESULTは学習入力へ入れず、確定結果は次レース以降だけに反映
- 現在この計算結果をどの予測方式にも自動接続していません。予想4頭抽出方式の判断材料として人間・LLMが参照する運用を想定しています

## 運用原則
- 発走前予測を固定保存
- 結果判明後の後付け変更は禁止
- 正式結果は別記録として分離
- 抽出漏れ・過大評価・僅差の取りこぼしを分類
- 結果から得た改善は次レース以降にのみ反映
- JRA公式データ、予想4頭抽出方式、オッズ歪み、トリガミ警告を競馬専用として管理

### 公式結果の取得範囲

`RaceDayCollectionPolicy`は24時間巡回せず、JRA開催日の9:00〜17:30（日本時間）だけ作動します。各開催競馬場の1R〜12Rを対象とし、障害競走、未確定結果、取得済みレースは除外します。発走予定時刻から5分以上経過し、結果状態が`official`になったレースだけを一度取得します。取得経路は許可されたJRA公式データ提供アダプターへ限定し、HTML変更時に誤った結果を学習させない構造です。

## 保守専用RSI

予測とは完全に分離した`racing_maintenance_rsi`が、予想4頭抽出方式の固定値（`EXTRACTION_METHOD`・`EXTRACTION_COUNT=4`）、凍結予測の追記禁止、危険なコード、秘密情報、GitHub Actionsを監査します。

JRA由来の外部JSON・CSV・HTMLは、許可形式、容量、実行形式偽装、構文、構造、SHA-256、マルウェア検査を通過したものだけを利用できます。ウイルススキャナー不在時は既定で遮断し、不合格ファイルは隔離できます。

保守専用RSIには、自動投票、予測ロジックの自己変更、`main`への自動マージ、投資側リポジトリへのアクセス権限を与えません。

## 競馬予想検証室 ↔ GitHub 実戦ループ

競馬予想検証室での実戦は次の固定手順で運用します。

1. 発走前に予想4頭・オッズ歪み・トリガミ警告を確定
2. PRE_RACEとして書き込み禁止の固定レコードへ保存（`freeze_four_horse_extraction`）
3. レース後に正式結果をRESULTとして別保存
4. EVALUATIONで馬連・ワイド・三連複・三連単の的中と、僅差の取りこぼし（`near_miss_horses`）を記録
5. 結果から得た改善は次レース以降にのみ反映し、同一レースのPRE_RACE予想は変更しない

ChatGPTがこのチャットで予想を行い、ユーザーが正式結果を与えた場合、GitHub接続が利用可能な範囲でこの記録形式へ反映します。通常チャットを開いていない間に自律的にJRA監視を続ける機能ではありません。

## 過去の結果答え合わせ（本格・簡易式λ時代の記録）

`python -m racing_lambda.simple_outcome_learning data/verification/2026-09-13-simple-outcomes.json`
で、発走前に公表した全馬順位とJRA正式結果からTop5抽出漏れ、過大評価、3着以内ラベルを生成できます。元の発走前順位は変更しません。この機能自体は旧λに依存していないため残していますが、`data/verification/`配下の過去記録は本格・簡易式λ時代のもので、削除した実装が生成した参考データとして保持しています。
